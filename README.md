# WiFi 密码清单（Windows 原生窗口程序）

**版本 v1.6.5** · 单文件 Windows 程序：双击即开，当场查看本机保存的 WiFi 名称与密码，可连接 / 断开 / 增删改配置，并导出精美的 HTML 报告。提供**安装版**与**绿色免安装版**两种下载。

- **无标题栏**：自绘标题带，可拖动、可四边缩放、Win11 圆角
- **深色 / 浅色主题**：标题带右上角切换，选择会被记住
- **连得上、改得动**：右键即可连接、断开、编辑密码与安全类型、切换自动 / 手动连接，也能新增与删除
- **信号环**：当前连接用环形表盘显示信号强度，与导出的 HTML 报告同一套设计
- **高 DPI 清晰**：声明 DPI 感知，125% / 150% / 200% 缩放下文字不虚、不被裁切
- **三种界面语言**：简体中文 / English / ไทย，标题带地球按钮随时切换，选择会被记住
- **关于**：标题带 ⓘ 按钮，显示版本、本机、系统与运行时信息，自动检查 GitHub 上的新版本，可一键复制版本信息
- **三语报告**：导出的 HTML 报告也能在中文 / English / ไทย 之间切换，默认跟随程序界面语言
- **两种安装方式**：安装版（开始菜单 + 桌面快捷方式 + 卸载项）或绿色免安装版（解压即用，不写注册表）
- **零依赖**：只用 .NET Framework 自带组件，不联网、不安装

## 二、下载与安装

去 [Releases](https://github.com/hengletime/WifiList/releases) 下载，两个文件任选其一：

| 文件 | 类型 | 说明 |
|---|---|---|
| `WifiList-Setup-1.6.5.exe` | 安装版 | 双击安装，默认装到 `%LOCALAPPDATA%\Programs\WifiList`（当前用户，**不需要管理员权限**）；创建开始菜单项与桌面快捷方式，写入「应用和功能」卸载项；卸载干净，不残留注册表 |
| `WifiList-1.6.5-portable.zip` | 绿色免安装版 | 解压即用，只有一个 `WifiList.exe`；不写注册表、不留安装痕迹，可放 U 盘 |

安装版支持静默部署：

```
WifiList-Setup-1.6.5.exe /S              静默安装（默认路径、不启动程序）
WifiList-Setup-1.6.5.exe --uninstall      交互式卸载
uninstall.exe                             交互式卸载（文件名即模式，不带参数）
uninstall.exe /S                          静默卸载
```

> 安装版本身也带三语界面（跟随系统语言，可在左下角切换），并会检测已安装版本，直接覆盖升级、保留原有设置。

### 怎么卸载

三种方式等价，都会弹出标题为「卸载 WiFi 密码清单」的确认窗口，点「卸载」即删除程序文件、开始菜单项、桌面快捷方式与注册表项，显示「已卸载」约 2 秒后窗口自动关闭：

| 方式 | 操作 |
|---|---|
| Windows 设置 | 设置 → 应用 → 已安装的应用 → 搜「WiFi 密码清单」→ 卸载 |
| 开始菜单 | 开始菜单 → WiFi 密码清单 → 「卸载 WiFi 密码清单」 |
| 安装目录 | 双击 `%LOCALAPPDATA%\Programs\WifiList\uninstall.exe` |

> **不要**运行下载的那个 `WifiList-Setup-1.6.5.exe` 来卸载——它是安装程序，双击就是安装界面（v1.6.1 起若把它改名成 `uninstall.exe` 也会进入卸载模式，但正确做法是用上面三种之一）。绿色免安装版无需卸载：删掉 exe 即可，它不写注册表、不建快捷方式。
>
> 卸载会清掉程序文件、`uninstall.exe` 本体和空的安装目录；**主题与语言偏好**（`%LOCALAPPDATA%\WifiList\theme.cfg`、`lang.cfg`）故意保留，重装后沿用。要彻底清干净，手动删掉这个文件夹即可。

| 结果 | 显示 | 按钮 |

### 右键菜单一览

```
连接到此网络           （当前行换成「断开当前连接」，二选一只出现一行）
────────────
复制                ▸  网络名称 / 密码
显示密码 / 隐藏密码      （有密码时才出现）
────────────
配置                ▸  编辑此网络…
                       设为自动连接 / 设为手动连接
                       ────────
                       删除此网络的配置（红色）
刷新列表
```

菜单分四组、常用项只留一行，次要动作收进「复制」「配置」两个二级菜单，行距也加大了，不再挤成一长条。

「编辑此网络…」复用「添加 WiFi」弹窗，只是预填了原值：改完保存时程序**先导出一份原配置到临时目录**，用新值重新写入；写入后重新读取列表核对安全类型，确认无误才删除旧配置（改名场景）。若写入失败，会自动把原配置还原回去，不会出现「改坏了又没了」的情况。

企业级 802.1X 与 WEP 配置无法用本表单重建（需要证书 / 账号），这两类行的「编辑」会置灰，请到系统「设置 → 网络和 Internet → WLAN → 管理已知网络」里改。

### 添加 WiFi

「添加 WiFi」弹窗里填：

- **网络名称（SSID）**
- **安全类型**：点击展开下拉列表 —— WPA2-PSK（AES）/ WPA3-SAE（AES）/ WPA-PSK（TKIP）/ 开放网络
- **密码**：WPA 系列需 8–63 位；开放网络自动禁用密码框
- **选项**：隐藏网络、自动连接、保存后连接

保存时程序生成标准 `WLANProfile` XML，用 `netsh wlan add profile ... user=current` 写入**当前用户**配置，因此不需要管理员权限。

### 删除 WiFi

`netsh wlan delete profile` 删除当前用户的配置。若该配置属于「所有用户」，需要右键 `WifiList.exe` → 以管理员身份运行。删除当前正在连接的网络会立即断线，程序会先提示。

## 七、导出 HTML 报告

点「导出 HTML 报告」→ 生成 `output\wifi-list-<时间戳>.html` 并自动用浏览器打开。

报告是自包含单文件（约 46 KB），特性：深浅双主题、搜索与筛选、密码打码后点击显示、一键复制、打印 / 存 PDF 友好。

**三语报告**：报告顶部右上角有 `中文 / English / ไทย` 分段按钮，点一下整套界面文案（表头、统计卡、标签、提示、页脚）即时切换，网络名称与密码原样保留；语言选择记在浏览器本地，下次打开沿用。默认语言由导出时的程序界面语言决定（现在这份报告导出时界面是中文，就是中文），也可以在地址栏追加 `?lang=en` / `?lang=th` 强制指定；在报告里切过之后同一次浏览保持，不写回文件。

## 九、实现要点（便于日后维护）

**1. 中文 SSID 必须走 XML，不能解析 netsh 文本**
`netsh wlan show profiles` 的中文输出在管道下会被按 GBK 截断（`远达2楼` → `杩滆揪2妤?`）。程序改用 `netsh wlan export profile key=clear` 导出标准 `WLANProfile` XML，再用 XPath 取值——**完全语言无关**，中文与明文密码都完好。

**2. 当前连接必须挑对网卡**
`Microsoft Wi-Fi Direct Virtual Adapter` 同样报告 `Wireless80211` 且状态为 `Up`，但它没有默认网关和 DNS。若按「第一个 Up 的无线网卡」取值，就会出现网关 / DNS / 链路速率全是 `-`（旧版正是这个问题）。现在按打分挑选：物理无线网卡 +100，虚拟适配器（virtual / Wi-Fi Direct / miniport / Hyper-V / VPN）−250，有 IPv4 +30，有网关 +40，有 DNS +10。

**3. `netsh wlan show interfaces` 可能有多段**
每个无线接口一段，只有已关联的那段含 `AP BSSID`。程序先按空行切段，再取含 BSSID 的段解析 SSID / RSSI / 信号。

**4. 无边框窗口仍保留原生手感**
`FormBorderStyle.None` + 自行处理 `WM_NCHITTEST`：边缘 6px 返回 `HTLEFT/HTTOP...` 得到原生缩放，标题带区域返回 `HTCAPTION` 得到原生拖动与双击最大化；`WM_GETMINMAXINFO` 把最大化尺寸限制在任务栏之外；`DwmSetWindowAttribute` 打开 Win11 圆角。

**5. 主题是运行时可变的**
`Ui` 里的调色板是可变静态字段，所有自绘代码在绘制时读取它，切换主题只需改字段 + 重设控件颜色 + `Invalidate`。选择保存在 `%LOCALAPPDATA%\WifiList\theme.cfg`。

**6. 高 DPI 必须声明感知，布局必须等比例放大**
未声明 DPI 感知时，Windows 把 200% 缩放当成「把 96 dpi 的位图放大两倍」，于是文字发虚；同时写死的 12–14 px 标签矩形比字体实际高度矮，字被切掉下半截。现在 `Program.Main` 第一件事是 `SetProcessDpiAwareness(1)`（系统级），并以 `dpi / 96` 作为全局缩放系数 `Ui.S`；所有布局与绘制常量都写成 96 dpi 设计值并过 `Ui.Z()`，字体用磅值（本身随 DPI 放大），三者比例一致。

**7. 任务栏图标来自窗口，不是 exe**
`/win32icon` 只改资源管理器里看到的 exe 图标；任务栏、Alt+Tab 取的是窗口的 `WM_GETICON`，即 `Form.Icon`。所以 `.ico` 同时以 `/resource` 嵌入，窗口构造时从清单资源读出赋给 `Icon`（并用 `SetCurrentProcessExplicitAppUserModelID` 固定分组）。

**8. 源码约定**
- `.bat` 必须是 **CRLF** 换行，否则 `^` 续行失效
- 源文件 UTF-8，编译带 `/codepage:65001`
- 不使用 C# 6+ 语法（字符串插值、`?.`、`nameof`、`out var`），以兼容 .NET Framework 自带编译器
- 多语言：所有界面文案都在 `src/Lang.cs` 的三列表里（`A("key", 中文, English, ไทย)`），代码只写 `L.T("key")` / `L.F("key", args)`；缺词条时回退中文
- 字体按语言切换：中文 → Microsoft YaHei UI，English → Segoe UI，ไทย → Leelawadee UI；`Ui.LoadFonts()` 重建整套字体，再由主窗口重建控件生效
- 切语言不重启：`MainForm.RebuildUi()` 释放全部子控件后重新 `BuildUi()`，再重新绑定已有快照（不重跑 netsh）
- 按钮宽度按文案实测（`Ui.TextW`），避免泰文比中文长而被截断

**9. 报告模板也是三语的，但不靠程序拼字符串**
`assets/template.html` 里带一张 68 条的 `TXT = {zh,en,th}` 词表和一个 `t()/tf()` 取值函数，所有静态文字留空、由脚本在 `renderAll()` 里填充。切换语言只重跑渲染函数，不刷新页面、不丢搜索词与已展开的密码。默认语言由程序注入 `/*__WIFI_LANG__*/` 占位符（`zh` / `en` / `th`）。

**10. 更新检查放在后台线程**
`UpdateCheck.Latest()` 用 `HttpWebRequest` 读 `releases/latest`，`ServicePointManager.SecurityProtocol = Tls12`（.NET 4.0 默认只谈 TLS 1.0，GitHub 会直接拒绝）；6 秒超时，任何异常都返回 `null`。UI 侧用 `ThreadPool.QueueUserWorkItem` + `BeginInvoke` 回主线程，`AboutForm` 打开时立即绘制、结果后到，绝不卡界面。

**11. 安装程序不依赖 Inno Setup**
`installer/Setup.cs` 是一个自带 payload 的 WinForms 小程序：编译时用 `/resource:build\WifiList.exe,WifiList.Payload.exe` 把主程序嵌进去，运行时释放到安装目录；快捷方式通过系统脚本宿主对象创建；卸载信息写 `HKCU\...\Uninstall\WifiList`，并把自己复制成卸载程序负责清理。默认装到 `%LOCALAPPDATA%\Programs\WifiList`，因此**全程不需要管理员权限**。绿色版就是同一个 exe 直接压 zip，两者二进制完全一致。

**12. 一次产出全部发布件的脚本**
`打包发布.bat` 依次做四件事：编译主程序 → 编译安装包（内嵌刚编好的 exe）→ 组装绿色版目录 → 写 `dist\`（`WifiList.exe`、`WifiList-Setup-<版本>.exe`、`WifiList-<版本>-portable.zip`）。任何一步失败都会把编译器原文打到控制台并停在 `build.log`。

**13. 卸载模式靠文件名识别，不靠参数**
`uninstall.exe` 是安装程序自身的副本，早先只认 `--uninstall` 参数，一旦参数丢失（双击、某些卸载入口）就会走成安装流程。现在 `Main` 里先看 `Application.ExecutablePath` 的文件名，是 `uninstall` / `uninst` 就直接进卸载模式；显式参数仍然优先，所以 `uninstall.exe /S` 依旧静默卸载。

**14. `Visible` 在 `Show()` 之前一律是 `false`**
WinForms 的 `Control.Visible` 取的是「自己和所有父级都可见」，窗体还没显示时整条父链都是不可见的，即使你刚把子控件的 `Visible` 设成 `true`，读回来还是 `false`。安装窗口原来用 `_btnBrowse.Visible` 决定要不要给它留宽度，构造函数里算出来永远是 0：路径框占满整行，「浏览…」从未 `SetBounds`，停在默认坐标 `(0,0)`，显示时正好压在深色标题条上。
规矩：**布局时的显隐判断必须用显式状态字段（如 `_uninstallMode`），不要读 `Visible`**；控件位置一律在 `OnShown` 里再排一次，避免构造期尺寸不准留有默认坐标的漏网控件。

**15. 装完就该消失，别等用户点关闭**
勾了「立即运行」时程序已经自己弹出来了，安装窗口再留着只会让人以为卡住。成功分支里先记下 `ran = _chkLaunch.Checked`，状态行换成「安装完成，程序已启动，本窗口即将关闭」，再用一个 `System.Windows.Forms.Timer` 在 1 秒后 `Close()`（卸载成功则 2.2 秒，留出读「已卸载」的时间）。注意 `System.Threading` 也导入了 `Timer`，写全名避免二义性。卸载要尽早退出还有个副作用红利：卸载程序自删的后台 shell 约定 5 秒后开始重试，窗口退得早，删除就一次成功。

**16. 界面版式要能被"无人值守"地核对**
安装程序除了正常参数，还认 `--render <png>` / `--render-remove <png>` / `--lang zh|en|th`：把窗口放到屏幕外 `Show()`，`DrawToBitmap` 存成 PNG 后退出。改版式时逐语截图目视核对，比人肉点安装程序可靠得多（主程序的报告导出也是同一套思路：`WifiList.exe --render out.png dark en`）。这三个开关在发布版里保留，方便日后回归。

**17. 选网卡时，虚拟适配器不能靠扣分压住**
给网卡打分（无线 +100、有 IP +30、有网关 +40、有 DNS +10、虚拟 −250）看似稳妥，实际有个致命前提：必须至少有一个真实候选参与比较。切换网络的一瞬间真实网卡会短暂 Down，被 `OperationalStatus != Up` 直接跳过，于是 Wi-Fi Direct 虚拟适配器（它也是 802.11 网卡、也带 `192.168.137.1`）成了唯一候选，分数再低也照样胜出——卡片于是显示了它的地址，而网关、DNS、链路速率全是「-」。改成 `if (IsVirtual(ni)) continue;` 硬排除后，没有候选就返回 null，让上层显示「-」，而不是把一块虚拟网卡的地址当成用户的连接。教训是：**扣分只对"有竞争者"的场景有效，不能当作过滤**。

配套还要处理时序——连上关联（association）不等于拿到地址（DHCP）。现在连接成功后先等 IPv4 就绪（最长 6 秒），再一次性读取；仍为空则 1.5 秒后自动重读，最多 4 次。这样切网时网卡正好在重启，卡片也会在几秒内自己补全，不必重启程序。

**18. 信号强度要走系统接口，不要解析 netsh 文本**
`netsh wlan show networks` 的输出是本地化的（中文机器上字段叫「信号」，英文机器叫 `Signal`），百分比还按 BSSID 分行打印，解析要按块切分；同一网络有多个热点时还得自己取最大。`WlanGetAvailableNetworkList` 直接给出每个网络 0–100 的信号质量，跨语言一致。结构体按偏移读取（`WLAN_AVAILABLE_NETWORK` 628 字节，SSID 在 +516、信号质量在 +604），省去 P/Invoke 结构体对齐出错的风险。

**19. 发布也是一条命令，且发完要自我终核**
`scripts/publish_release.py <版本>` 用 Python 标准库直连 GitHub API（不依赖 gh、不依赖 PowerShell），流程是：校验四处版本号一致 → 校验 dist 两件产物非空 → 把 `RELEASE_NOTES_v<版本>.md` 的 `<!--SHA-->` 换成两件的 SHA-256、去掉与页面标题重复的首行 H1 → 创建或**更新**已有的同名 Release（幂等）→ 逐件上传（线上同名且 digest 相同就跳过）→ 最后回读线上资产，把 `digest` 与本地 sha256 逐字比对，不一致直接失败。
令牌不进代码：先 `mkdir -p .tmp && printf "protocol=https\nhost=github.com\n\n" | git credential fill > .tmp/gh_cred`，脚本只读 `password=` 那一行，发完立刻 `rm -rf .tmp`（`.tmp/` 已在 `.gitignore` 里）。
写这支脚本的直接动因是一次教训：手动调 API 时少写一个字段不会报错，只会安静地留一张残缺的 Release 页。

**20. `netsh` 的退出码不是成功证据**
`netsh wlan` 做不成事时经常也返回 0。最典型的是名字以 `#` 开头：解析器把那之后全当注释，于是它去找一个名字为**空串**的档案，报「任何接口上都找不到配置文件「」」——引号里是空的——退出码却是 0。所以 `delete profile name="#X"` 既不报错也不删除，用户看到的是「编辑改名后多出一条」。加引号、`^`、反斜杠、多余空格全都没用，这个名字无法用 netsh 表达。
现在的写法是先做后验：跑完 netsh 立刻用 `WlanGetProfileList` 回读档案列表，确认真的消失了才算成功；仍在则改用 `wlanapi.dll` 的 `WlanDeleteProfile`（P/Invoke，UTF-16 字符串直给服务，普通权限即可），删除后再回读一次。同一根因波及的三处也一并改掉：备份导出改成「按名字导不出就整体导出再按 XML 的 `<name>` 挑」；切自动/手动改成「导出原始 XML → 替换 `<connectionMode>` → `add profile filename=` 导回」（保留密钥与 802.1X）；连接改走 `WlanConnect`，并按「哪个接口存着这份档案」挑网卡，顺带避开 Wi-Fi Direct 虚拟网卡。
排错开关：`WifiList.exe --delete-profile "<名字>"`、`WifiList.exe --set-mode "<名字>" auto|manual`，打印结果后退出，失败时退出码为 1。

**21. `WlanScan` 只是"开始扫描"，结果要几秒才陆续到齐**
发起扫描后立刻读 `WlanGetAvailableNetworkList`，拿到的不是"最新列表"，而是**残缺列表**：系统按频段逐个扫，读到什么给什么。实测一次刷新（每 700 ms 读一次）：t=0 只有 1 个网络（当前关联的那个 BSS），t=700 ms 仍是 1 个，t≈1.4 s 变成 5 个，t≈2.1 s 12 个，t≈4.9 s 14 个。这就是"明明在范围内的第二个网络显示「—」，再点一次刷新才出现"的原因——第二次刷新落在 5 秒节流内没有重新扫描，读到的是上一轮已经扫完的列表。
现在 `Load()` 里记下 `snap.Scanned`，主窗口据此起一个 700 ms × 8 次（约 5.6 秒）的补救定时器，每次只做一件事：`WifiCollector.RefreshSignals()` 重新读一次并**只增补不抹除**（`allowClear:false`）——扫描期间列表时多时少，抹除会让行在「91%」和「—」之间闪。顺序变了就整体重建，没变就只改「信号」单元格，所以看不见闪屏。全部就绪后定时器自行停止。

## 十、常见问题

**打开后网关 / DNS 还是 `-`**
先跑 `WifiList.exe --diag-net d://diag.txt` 看 `winner` 是哪块网卡：
- `winner: (none ...)` → 真实网卡此刻不在 Up 状态，或只有 Wi-Fi Direct 虚拟适配器在场（它带 `192.168.137.1` 但没有网关和 DNS）。程序会在 1.5 秒后自动重读，最多 4 次。
- `winner` 是物理网卡但 IP 为空 → 热点没分配地址（DHCP 失败），换一个网络或手动设 IP。
- `winner` 是 `Microsoft Wi-Fi Direct Virtual Adapter` → 不该发生（v1.6.3 起虚拟适配器被硬排除），出现了请把 diag.txt 发我。

v1.6.3 之前这个现象还有个专门的原因：切换网络时真实网卡短暂 Down，虚拟适配器被当成当前网卡，于是显示它的地址、网关与 DNS 为空——重启程序才好。现在不会了。

**刷新后信号列少一个网络，再刷新一次才出来**
v1.6.5 已修。根因不是漏扫，而是**读得太早**：`WlanScan` 只负责让网卡开始扫描，结果按频段陆续返回（实测 1 → 5 → 12 → 14 个网络，跨度约 5 秒），程序在扫描刚发起时就读，拿到的是残缺列表。现在补读 8 次、只增补不抹除，约 1 秒内就会自己补齐，不必再点刷新。

**切换网络时提示「连接未成功」**
v1.4.0 起会把网卡名显式传给 `wlan connect`，失败后自动断开重连一次（最多约 18 秒）。仍失败时弹窗里的 netsh 原文现在是可读的中文，可直接判断原因：
- `配置文件“xxx”…` / `没有分配给指定接口的配置文件` → 该配置不属于这张网卡，删掉后重新添加
- 提示需要密钥或验证失败 → 密码已变，用「配置 → 编辑此网络…」改密码
- 提示不在范围内 → 热点信号不够，或 5G 频段距离太远

**弹窗里出现乱码**
v1.4.0 已修复：netsh 在重定向输出时发的是 UTF-8，而旧版本按 GBK 解码，中文提示与中文 SSID 会变成「闂晱鑼囧洖…」这样的乱码。现在按原始字节读取，先严格按 UTF-8 解码，失败才回退到系统 ANSI 代码页。

**添加或删除失败**
看弹窗里的 netsh 原文。最常见是权限不足（配置属于「所有用户」）→ 右键 `WifiList.exe` 以管理员身份运行。

**杀毒软件报毒**
程序会调用 `netsh` 并读取 WiFi 密码，这类行为与「WiFi 密码查看器」特征一致，可能被启发式规则误判。源码全部在本目录，可自行审阅或加入信任。
